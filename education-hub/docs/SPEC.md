# 교육 프로그램 허브 · 5학년 도서 추천 앱 개발명세서

## 1. 프로젝트 기본 정보
가칭 ‘책별 허브’. 앞으로 개발할 교육 프로그램을 카드로 모아 실행하고, 첫 앱에서 학생의 관심 주제와 읽기 난이도에 맞는 책을 추천한다. 학생이 책을 고르는 부담을 줄이고 교사는 새 프로그램을 코드로 추가할 수 있어야 한다. 성공 기준은 허브 진입부터 추천 확인까지 혼자 완료하는 것이다.

## 2. 사용자 정의
- 주요 사용자: 초등 5학년 학생. 최종 확장 대상은 3~6학년.
- 보조 사용자: 도서 목록과 분류를 검토하는 교사.
- 운영 담당자: 교사(가정). 코드와 데이터 파일을 수정한다. 웹 관리자 화면은 없다.
- 학생은 공개 목록을 조회하고 조건을 선택한다. 데이터 수정 기능은 제공하지 않는다.

## 3. 사용 환경과 실행 플랫폼
설치 없이 사용하는 반응형 웹앱. 학교 태블릿과 PC를 동등하게 지원한다. 브라우저 종류와 학교 네트워크 제한은 미결정이며 실제 학교 기기로 확인한다. 최초 페이지 로딩은 인터넷 또는 로컬 개발 서버가 필요하다. 로딩 후 추천 계산은 기기 안에서 수행한다. 완전 오프라인 재접속과 PWA 설치는 MVP에서 제외한다.

## 4. 핵심 사용자 시나리오
- 학생: 허브에서 도서 추천 카드 실행 → 5학년 안내 확인 → 관심 주제와 난이도 선택 → 추천 버튼 → 책과 추천 이유 확인 → 조건 변경 또는 허브 복귀.
- 교사: 후보 도서의 정확한 판본·주제·난이도 검토 → 데이터에서 승인 → 검증 후 업데이트.
- 예외: 조건 미선택은 해당 항목 안내. 일치 도서가 없으면 조건 변경 안내. 데이터 오류는 사용 가능한 항목만 표시하되 개발 검증에서 오류를 보고한다. 전체 목록이 비면 ‘추천할 책을 준비 중이에요’ 표시.

## 5. 사용자 흐름
허브(SC-001) → 사서 선택(SC-002) → 결과(SC-003) → 다시 선택 또는 허브. 프로토타입은 학년을 5학년으로 고정 표시한다. 후속 버전에서 검토된 학년 데이터가 추가되면 3~6학년 선택을 활성화한다.

## 6. MVP 범위
필수: 앱 카드 목록·실행·복귀, 주제·난이도 선택, 등록 도서 추천, 조건에 근거한 이유, 빈 상태와 오류 안내, 반응형·키보드 조작.
후속: 3~6학년 목록, 학교 보유 도서 표시, 인쇄.
제외: 화면에서 앱 등록, 로그인, 학생 기록·즐겨찾기 저장, 대출 관리, 자유 대화, 외부 생성형 AI, 서버·DB, 분석 추적, 배포 실행.

## 7. 기능 요구사항
모든 기능은 학생 대상이며 공개 페이지 로딩이 사전 조건이다. 우선순위는 모두 필수다.

| ID | 목적·입력 | 처리·출력 | 예외·오류 | 화면 | 완료 기준 |
|---|---|---|---|---|---|
| FR-001 | 앱 찾기; 앱 카드 클릭 | 앱 목록에서 유효한 경로로 이동 | 잘못된 경로는 허브 복귀 안내; 준비 중 카드는 실행 불가 | SC-001 | AC-001 |

| FR-003 | 책 추천; 유효한 선택 | 5학년·승인 도서 중 주제와 난이도 일치 항목 최대 3권 반환(가정); ID 순으로 안정 정렬 | 0권이면 조건 변경 안내; 1~2권이면 실제 수만 표시 | SC-003 | AC-003, AC-004 |

추천은 규칙 기반이다. ‘AI 사서’라는 이름을 쓸 경우 화면에 ‘등록된 도서 목록과 선택 조건으로 추천해요’라고 설명한다. 생성형 AI가 분석하거나 학습했다고 표시하지 않는다.

모든 화면은 학생에게 공개한다. 별도 로그인 로딩은 없다. 목록 로딩 실패 시 재시도 버튼을 제공하고 실제 대기 없이 가짜 로딩을 넣지 않는다. 태블릿 세로는 1열, 넓은 화면은 2~3열. 제목·본문·버튼을 장식 요소가 가리지 않는다.

## 10. 데이터 요구사항
프로그램 목록과 도서 목록은 앱에 포함된 정적 파일이다. 교사가 생성·수정·삭제하며 코드 저장소로 버전 보관한다. 학생 입력·추천 이력·이름·학번은 영구 저장하지 않고 현재 화면 메모리에서만 처리한다. localStorage·쿠키·추적 도구는 추가하지 않는다. 보관 기간과 학생 데이터 삭제는 해당 없음: 학생 데이터를 저장하지 않는다.

## 11. 데이터 모델
DB 없음. 정적 JavaScript 배열 또는 JSON을 사용한다.

| Book | id:string, title:string, author:string, publisher:string | 모두 필수; id 고유 | 삭제 시 추천 후보에서도 제거 | 없음 |
| Book | grades:number[], topics:string[], difficulty:easy/standard/challenge | 모두 필수 | 3~6 범위와 주제 허용값 검증 | 없음 |

## 12. 시스템 구성
프론트엔드만으로 충분하다. 정적 목록 → 선택값 검증 → 기기 내 필터링 → 이유 템플릿 → 결과 카드. 앱 레지스트리, 도서 데이터, 추천 함수, 화면, 스타일을 분리한다. 백엔드·인증·DB·업로드 저장소는 해당 없음. 공개 정적 파일 자체는 누구나 읽을 수 있으므로 비밀이나 학생 정보를 포함하지 않는다.

## 13. API 및 외부 서비스
MVP에서 해당 없음. 외부 AI/API 호출, API 키, 비용 발생 호출이 없다. 출처 링크는 교사가 확인하기 위한 참고다. 학생 입력을 URL에 넣거나 외부로 전송하지 않는다. 이후 생성형 AI 도입은 별도 범위이며 비밀키 보호를 위한 서버 중계를 포함해 다시 설계한다.

## 14. 로그인과 권한
로그인·비밀번호·세션·계정 삭제는 해당 없음. 학생용 화면에는 수정 기능이 없다. 교사의 변경은 소스 파일 편집으로 수행하며 로그인처럼 보이는 가짜 관리자 기능을 만들지 않는다.

## 17. 권장 기술 스택
권장: HTML + CSS + JavaScript 모듈과 정적 데이터. 작은 첫 앱에 빌드·라이브러리 설치 부담을 줄이고 사용자 정의 스티커 디자인을 직접 표현한다. UI·테스트는 브라우저 기반, 추천 함수는 독립 검증 가능하게 구성한다. 백엔드·DB·인증·외부 UI 라이브러리는 해당 없음. 초기 난이도 낮음, 앱 수 증가에 따른 화면 코드 관리 부담은 있다.
대안: 화면과 상태가 복잡해질 때 컴포넌트 기반 프레임워크로 전환. 현재는 구체적인 제품·버전·요금제를 선택하지 않는다. 새 의존성 도입 시 공식 문서에서 출처·지원·라이선스·취약점을 검토한다.

## 18. 배포 및 운영
개발·테스트는 로컬 정적 서버와 합성 데이터. 운영은 정적 호스팅을 사용할 수 있으나 공급자·비용·도메인은 미결정이다. 배포 실행은 별도 요청에 따른다. 앱스토어·비밀 환경변수 불필요. 교사가 데이터와 업데이트를 담당한다(가정). 코드·승인 목록을 버전 관리하고 장애 시 이전 정상 버전으로 복구한다. 비용 요소는 선택할 호스팅·도메인뿐이며 무료 한도는 아직 검증하지 않았다.

## 19. 테스트 계획
추천 함수: 승인 여부·학년·주제·난이도 일치, 최대 3권, 0~2권, 중복 ID·이상값. 실제 책과 분리된 합성 데이터 사용.
사용 흐름: 허브 → 선택 → 결과 → 재선택 → 복귀; 미선택, 빈 목록, 잘못된 경로. 태블릿 터치와 PC 키보드 모두 검증.
시각 확인: 화면 폭 3종, 200% 확대, 대비, 포커스, 디자인 토큰, 그림자·그라디언트·겹침 없음.
개인정보: 새로고침·저장소·네트워크·URL·로그에 학생 선택이 남거나 전송되지 않는지 확인. 권한·백업 DB 테스트는 해당 없음.

## 20. 인수 조건
- AC-001 (FR-001): Given 허브, When 사서 실행, Then 5학년 추천 선택 화면 표시.
- AC-002 (FR-002): Given 조건 미선택, When 추천 클릭, Then 누락 항목 안내와 포커스 이동; 결과 생성 안 함.
- AC-003 (FR-003): Given 일치 승인 책 4권과 미승인/다른 학년 책, When 추천, Then 일치 승인 책만 최대 3권 표시.
- AC-004 (FR-003): Given 0/1/2권 일치, When 추천, Then 0권은 조건 변경 안내, 나머지는 실제 권수만 표시; 조건을 몰래 완화하지 않음.
- AC-005 (FR-004): Given 결과, Then 확인된 서지와 선택 조건을 근거로 한 이유 표시; 없는 줄거리·대출 가능 여부를 주장하지 않음.
- AC-006 (FR-005): When 다시 고르기, Then 선택값 유지; When 허브 복귀, Then 앱 카드 표시.
- AC-007 (FR-006): Given 새 레지스트리 항목·검토된 학년 데이터, Then 데이터 변경만으로 추가 가능; 프로토타입에는 5학년만 활성화.
- AC-008 (NFR-001~003): Given 지원 폭·키보드·200% 확대, Then 전체 핵심 흐름 완료, 내용 겹침·가로 스크롤 없음, 학생 입력 저장·전송 없음.

## 21. 구현 순서
1. 정적 앱 구조·허브·디자인 토큰 구성. 허브 카드와 복귀 흐름 확인.
2. 합성 데이터로 추천 함수·선택·결과 구현. AC-002~006 검증.
3. 출처 기반 후보 데이터 정리와 교사 검토 상태 반영. 미승인 제외·서지 확인.
4. 반응형·접근성·오류 처리 완성. AC-001~008 검증하고 실행 안내 작성.
각 단계는 구현 → 검증 → 결과 확인 후 진행한다. 도서 검토를 기다리는 동안 합성 데이터로 기능 구현할 수 있다. 학생용 실제 추천 공개는 승인 도서가 마련된 뒤 진행한다.

## 22. 위험요소와 대응
- ‘AI’ 명칭 오해: 규칙 기반임을 설명하고 생성형 AI 능력을 주장하지 않는다.
- 자료 분류 부정확: 주제·난이도는 교사 검토 상태로 관리한다. 출처 목록을 전국 공통 필독 목록이라고 표시하지 않는다.
- 특정 조합 0건: 결과를 만들어 내지 않고 선택 변경을 안내한다.
- 디자인 충돌: 한글 가독성·태블릿 대응을 우선한다는 합의를 적용한다.
- 학교 기기 제한: 실기기 브라우저·네트워크 확인 후 배포처 결정.
- 데이터 확장 부담: 3~6학년 공통 모델과 레지스트리를 유지한다.

## 23. 가정과 미결정 사항
확정: 학생 사용, 최종 3~6학년/첫 5학년, 관심 주제+난이도, 교사 검토 후보 목록, 코드로 앱 추가, 태블릿·PC, 학생 가독성 우선 디자인.
가정: 로그인·학생 기록 없음, 추천 최대 3권, 단일 주제 선택, 시스템 한글 글꼴, 교사 운영.
구현 전 또는 검토 중 결정: 주제·난이도 분류와 개별 판본, 승인 도서. 안전한 기본값은 미승인 상태다.
나중 결정: 허브 이름, 3~6학년 확장 시점, 인쇄, 호스팅·도메인·예산. 실사용 전 학교 기기와 정책 확인.

## 24. 비개발자를 위한 쉬운 요약
학생이 허브에서 사서를 열고 관심 주제와 읽기 난이도를 고르면, 미리 준비한 책 가운데 맞는 책을 보여준다. 첫 버전은 5학년이며 나중에 3~6학년 책을 추가한다. 서버와 회원가입 없이 작동하고 학생 이름이나 기록을 저장하지 않는다. 첨부 디자인의 밝은 스티커 분위기를 살리면서 한글과 버튼을 크게 만든다.

## 25. 기술 선택 이유 요약
브라우저는 태블릿과 PC에서 설치 없이 접근할 수 있다. 정적 목록과 기기 내 계산이므로 백엔드·DB가 필요 없다. HTML/CSS/JavaScript는 작은 첫 버전의 의존성을 줄이고 지정 디자인을 직접 구현하기 쉽다. 향후 공동 수정·동기화·생성형 AI가 필요해지면 서버와 권한을 다시 설계한다.

3. 승인 목록 적용 후 학교 태블릿·PC에서 확인하고 배포를 별도 요청한다.

### 1단계: 허브와 화면 틀

### 2단계: 추천 핵심 흐름
11절 모델의 합성 데이터만 사용해 FR-002~004/006을 구현하세요. 승인·5학년·주제·난이도를 모두 만족하는 도서를 안정 정렬해 최대 3권 표시하세요. 0권·미선택·잘못된 데이터는 명세대로 처리하세요. 이유는 선택 조건에 근거한 템플릿으로 만들고 줄거리를 지어내지 마세요. 추천 함수의 AC-002~007을 검증하세요.
