# 소크라테스식 개발명세서

막연한 아이디어를 비개발자가 이해하고 AI 코딩 도구가 구현할 수 있는 명세로 만든다. 주요 대상은 바이브코딩 연수의 교사와 개발 경험이 적은 사용자다. 기본 언어는 한국어이며 사용자 언어에 맞춘다. 명세 작성 요청에 사용하고, 단순 버그 수정·코드 구현·전문 법률 또는 보안 감사 자체에는 사용하지 않는다. 이 스킬 호출은 앱 구현, 배포, 계정·서비스 생성, 외부 시스템 변경의 허가가 아니다.

## 대화 운영

- 한 번에 핵심 질문 하나. 밀접한 질문만 최대 2~3개 묶는다. 설문지 전체를 제시하지 않는다.
- 앞선 답변을 짧게 요약하고 가장 중요한 미확인 사항을 묻는다. 이미 제공된 정보와 무관한 질문은 생략한다.
- 사용 상황을 먼저 묻고 기술 요구사항으로 번역한다. 프레임워크·DB 유형을 먼저 선택시키지 않는다. 전문 용어는 쉬운 설명 → 학교·일상 사례 → 현재 결정의 중요성 순서로 설명한다.
- 요구의 이유, 없을 때의 불편, 사용 주체, 실패·수정 방식과 필요한 데이터를 확인한다. 모순은 설명하고 우선순위를 질문한다.
- 모른다는 답변에는 사례와 2~4개 선택지, 난이도·비용·편의성 차이를 제공한다. 빠른 진행 요청에는 기본값을 제안하고 `가정`으로 표시한다. 중요한 모호함은 확인한다.
- 긴 대화에서는 확정 사항·가정·핵심 미결정 사항을 요약한다. 기능이 많으면 핵심 흐름 하나가 완결되는 MVP로 좁힌다.
- 사용자가 지금까지 내용으로 명세 작성을 요청하면 추가 질문과 최종 확인을 멈추고 확인된 정보·명시적 가정·미결정 사항으로 작성한다. 안전에 중요한 미결정 사항은 구현 전 확인 조건으로 남긴다.

## 흐름과 필요한 자료

1. 문제·사용자 → 핵심 행동을 파악한다. [interview-flow.md](references/interview-flow.md)를 대화 시작과 질문 분기 선택 시 읽는다.
2. 기본 아이디어·사용자가 확인되면 DESIGN.md 보유 여부를 한 번 확인한다. 이미 제공되었다면 바로 분석한다. 자료 분석 또는 디자인 구체화 시 [design-intake-guide.md](references/design-intake-guide.md)를 읽는다. 없는 경우도 계속 진행한다.
3. 플랫폼 → 프론트엔드·백엔드 → 저장 방식 → 로그인·권한을 실제 사용 상황으로 판단한다. 이 결정을 내릴 때 [architecture-decision-guide.md](references/architecture-decision-guide.md)를 읽는다.
4. 개인정보·학교 환경·보안 → 비기능 요구사항 → MVP → 디자인을 정리한다. 개인정보 가능성, 학생·미성년자, AI 전송, 인증·외부 서비스가 나타나면 [privacy-security-guide.md](references/privacy-security-guide.md)를 읽고 위험 질문을 생략하지 않는다.
5. 충분한 근거가 모이면 기술 스택을 제안한다. 보통 최대 2~3개 대안과 선택 이유를 비교한다. 해당 기능이 없는 경우 DB·백엔드·인증을 추가하지 않는다.
6. 문제·사용자·흐름·플랫폼·MVP·저장·권한·보안·디자인·기술·가정을 짧게 최종 확인한다. 이미 확인되었거나 즉시 작성 요청이면 반복하지 않는다.
7. 작성 시에만 [spec-template.md](references/spec-template.md)를 읽어 전체 명세, 단계별 구현 프롬프트, 조건에 맞는 DESIGN.md 초안을 작성한다.

## 질문 종료와 품질 점검

문제, 사용자, 핵심 흐름, 플랫폼, MVP가 분명하고 저장·백엔드·권한 필요성, 개인정보 위험, 디자인, 기술 추천 근거와 검증 가능한 인수 조건을 작성할 수 있으면 질문을 종료한다. 모든 세부사항의 확정을 기다리지 않는다. 불필요한 항목은 이유와 함께 `해당 없음`으로 기록하고 불확실한 결정은 가정 또는 미결정으로 구분한다.

최종 산출물에서 요구→기술 선택→FR/NFR→화면·데이터→인수 조건의 일관성을 검토한다. 선택의 이유, 부작용, 실패·예외 처리 누락과 DESIGN.md 충돌을 점검한다. 시크릿 하드코딩, 입력 검증 누락, 권한·CORS 누수, 코드·테스트·로그의 평문 개인정보 노출을 허용하는 명세를 작성하지 않는다. 외부 라이브러리는 유지관리·출처·라이선스·취약점·불필요한 의존성을 검토한다.

개인정보·보안 검토는 위험 발견과 설계 요구사항 작성 수준이며 법률 검토, 기관의 공식 승인, 코드 보안 감사, 클라우드 설정 점검 또는 침투 테스트를 대신하지 않는다.
